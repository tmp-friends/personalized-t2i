技術解説

好みを選ぶだけで、画像が変わるしくみ

この展示の実装が、どう動いているかを1ページにまとめました。中心になるのは、テキストエンコーダーの中で好みを混ぜる FAN です。

1全体の流れ

来場者が決めるのは「どの画像のどこが好きか」だけです。それが Reference Prompt（カードに付けた説明文）になり、テキストエンコーダーの段階で Target Prompt（お題の文）に混ざります。

  1. 好きな画像を選ぶ最大36枚の候補の一覧から、合計3〜10枚。
  2. 好きな側面を指定する選んだ画像は最初「全部好き」（色・光・描画・雰囲気のすべて）になっていて、好きなところだけに絞れます。強さ strength は 1 / 2。
  3. 確認済みの説明文を Reference Prompt にする指定した側面に付いた短い英語の句を集めて、重み付きの Reference Prompt リストにします。
  4. FAN で Target Prompt をエンコードするTarget Prompt と Reference Prompt リストを一緒にテキストエンコーダーへ入れ、好みを混ぜた埋め込みを作ります。
  5. SDXL で生成するIllustrious XL v2.0 が 4つの seed で1枚ずつ描きます。

2FAN の仕組み

FAN（Foundation Encoders Are All You Need for Preference-Aware Personalization, CVPR 2026）は、画像生成モデルに好みを伝えるためにテキストエンコーダーの self-attention だけを組み替える手法です。追加の学習も、アダプターのような追加の構造も使いません。展示は公式実装を固定 commit 9d0b76843f64 のまま、SDXL の2つのテキストエンコーダー（CLIP-L と OpenCLIP bigG）の両方に適用しています。

1回のエンコードで起きること

Target Prompt と Reference Prompt をそれぞれ77トークンにそろえ、次の並びで1つのバッチにしてテキストエンコーダーへ入れます。

Target PromptPA で Reference Prompt を混ぜる本体。最後にこの出力だけを使う
Target Prompt の複製通常の self-attention のまま進む
Reference Prompt 1 … Rそれぞれ通常の self-attention のまま進む
  1. 複製と Reference Prompt は、ふつうにエンコードされる各層で元の self-attention をそのまま通ります。Reference Prompt どうしが混ざることもありません。
  2. Target Prompt だけが personalized attention を行うQuery は Target Prompt 自身から、Key と Value は同じ層の「Target Prompt の複製」と「全 Reference Prompt」を連結したものから作ります（図 (b) の ‖）。Q・K・V の射影には元の層の重みをそのまま使います。
  3. Target Prompt の出力だけを取り出すエンコードが終わったら、Target Prompt の hidden states を prompt_embeds として生成モデルへ渡します。差し替えたメソッドはエンコードのたびに元へ戻します。

Personalized Attention (PA) の配分

Target Prompt の各トークンの attention（PA）は、Target Prompt と Reference Prompt に次の割合で分けられます。

PA = (1 − α) × softmax(Target Prompt) ‖ α × Σr (wr / Σw) × softmax(Reference Prompt r)softmax は文ごとに別々に計算し、‖ は連結。wr は Reference Prompt r の weight

Target Prompt への attention は通常どおり softmax して合計 1 − α。Reference Prompt の側は、Reference Prompt ごとにその77トークンの中で softmax してから weight を掛け、Reference Prompt 全体の合計が α になるように割り直します。つまり α は「Reference Prompt 全体にどれだけ回すか」、weight は「その中で Reference Prompt どうしをどう分けるか」を決めます。展示の α は 0.5 です。

α = 0 なら、Target Prompt の複製（Reference Prompt を使わずにエンコードされた文）だけを見ることになり、Reference Prompt を使わないエンコードと同じ結果になります。また CLIP のテキストエンコーダーは前のトークンしか見ない因果マスクを持つため、Target Prompt の i 番目のトークンが見られるのは、複製と各 Reference Prompt でも先頭から i 番目までのトークンです。

どの層で混ぜるか

公式実装では skip_pa で「PA を行わず通常の self-attention のままにする層」を指定できます（図 (c) の SA の層）。展示では入力側の 0〜7 層目を SA のままにし、それより出力側の層だけで Reference Prompt を混ぜます。hidden states は最終層の1つ手前から取るので、画像に効いている PA の層は次のとおりです。

CLIP-L
12層のうち 8〜10 層目の3層
OpenCLIP bigG
32層のうち 8〜30 層目の23層

pooled 埋め込みと ClassTokenDecoder

SDXL はトークンごとの hidden states に加えて、文全体を1本にまとめた pooled 埋め込みも使います。通常は文末トークンの位置から取りますが、Reference Prompt を混ぜた系列ではどの位置が文全体を代表するかが変わります。そこで FAN は、最終層の hidden states から各トークンの得点を出す小さな分類器 ClassTokenDecoder（2層の MLP）を使い、得点が最も高い位置から pooled を取ります。重みは公式リポジトリ同梱の weight/L.pth と weight/bigG.pth で（sha256 は設定に固定：L e35c04b57c42… / bigG 35cc21f7e6bf…）、エンコーダー本体は学習し直しません。展示の既定設定では pooled を Reference Prompt を使わない値に置き換えるため（4章）、画像に効いているのは hidden states 側の混合です。

Tailored profiling（Reference Prompt の選別）

Reference Prompt が多いとき、公式実装は sample_size の割合だけ Reference Prompt を選びます。まず Target Prompt とのトークン単位の類似度に weight を掛けた値で候補を絞り、次にその中から、Target Prompt やすでに選んだ Reference Prompt と似ていないものを順に選びます（weight が大きい Reference Prompt ほど選ばれやすくなります）。近いものだけを集めるのではなく、好みの幅を少ない Reference Prompt で覆うための選び方です。展示では選別せず、選ばれた Reference Prompt をすべて使います（4章）。

来場者ごとの追加学習はしません。生成モデルもテキストエンコーダーも更新しません。好みはエンコードのたびに、Reference Prompt として attention に混ぜるだけです。

3Reference Prompt の作り方

Reference Prompt にするのは画像そのものではなく、画像に付けた説明文です。カードは catalog-v2 の 64枚（4被写体 × 16表現）で、色・光・描画・雰囲気の側面ごとに短い英語の句を持っています。実画像を見て側面ごとに確認できたカードだけを展示に出します。

例：確認済みカード「街角の少女 · 暖かな琥珀色・鉛筆のラフスケッチ」に付いている句
色warm color palette, amber tones
光overcast, diffused light, soft shadows
描画sketch, visible pencil lines, rough drawing
雰囲気serious, stern expression

被写体「街角の少女」を表す語は、句に含まれていません。

被写体語を含めない
句は表現（色・光・描画・雰囲気）だけを書き、被写体を表す語を入れません。カードの被写体もお題と重ねていないので、「被写体が好き」と「表現が好き」を切り分けられます。
重みの付け方
句ごとの weight = カードの strength（1 / 2）× 側面ごとの倍率 aspect_gain（0.5 / 1 / 2）。
重複は1件にまとめる
複数のカードで同じ句が選ばれたら、Reference Prompt は1件にまとめて weight を合算します。
「外す」は除去
外した画像や側面は重み0で残すのではなく、Reference Prompt リストから取り除きます。選ばなかった画像を負の重みに変えることもしません。

4検証で決めた設定

エンコーダーの設定は configs/fan-policies.json だけが持ち、既定は mask_skip8_v1 です。サーバーが解決し、画面やリクエストからは変えられません。

skip_pa = 0〜7
入力側の 8 層では personalized attention を行いません（CLIP-L・bigG の両方に同じ番号を適用）。入力側の層で混ぜると Reference Prompt 由来の全体的な「もや」がかかり、お題の被写体・構図・衣装の指定が崩れやすかったため。
use_attn_mask = true
Reference Prompt の padding トークンを personalized attention から除外します。上流の FAN は padding マスクがあると causal mask を外す実装になっており、これが旧設定（false）の理由だった：マスクを使うと α=0（Reference Prompt の影響がないはず）でもTarget Prompt のエンコードが変わってしまっていた。exhibit/src/exhibit/fan_mask.py がこれを修正し、Reference Prompt 側だけをマスクするので、Target Prompt のエンコードは plain のパイプラインと同一になる（Reference Prompt なしで確認：最大絶対差 0.0）。e10 run B（SDE）で legacy_exhibit と比較すると、暖色−寒色の差は +5.0（legacy +4.4、どちらも有意差なし）、彩度は −10.9（legacy −1.5）、Δtarget は −0.006（legacy 0.000）——見た目は legacy とほぼ変わらず、修正済みのマスクを使う設定を既定にするために選びました。
alpha = 0.5
反映の強さ。当初の確認で α=0.6 までお題の指定が保たれたため、その上限の内側に置いています。0.7 では衣装とポーズが変わる（e10）。強く反映するほど良いとは限りません。
pooled_mode = plain
pooled 埋め込みは Reference Prompt を使わない（plain）値を使います。上流からの意図的な逸脱です。公式の ClassTokenDecoder が padding トークンを終端と誤検出するため。pooled を EOS 位置でパーソナライズする fan_eos も e10-faneos で試したが、暖色方向のドリフトが増えるだけで双方向の反応性は改善しなかった。公式どおりの pooled は別の登録 policy で評価と比較に使っています。
skip = -2
hidden states は最終層の1つ手前から取ります（公式の SDXL 設定と同じ）。
profiling
Reference Prompt をすべて使う（選別しない）。

登録済みの別 policy：legacy_exhibit, mask_skip1_v1, official_encoder, strong_v1。既定は所有者判断で2段階切り替えました：2026-09-22 に legacy_exhibit から mask_skip1_v1 へ（実験 e10-mask run B、experiment hash 0bf81bf739ec880cd083aaaa1cd1e222cc3bfe8600765ef4d9914e03878de6b5）、2026-09-23 に mask_skip1_v1 から mask_skip8_v1 へ（experiment hash ead995b8787381d5b7daaf8081c820461a581bb58bb79961010d31052a2d523e、e11-sampler と legacy-family 比較のあと）。legacy-family 比較（docs/reports/fan-personalization/strength/e10-mask/legacy-family-*.jpg）で mask_skip1_v1 はどの Reference Prompt でも暖色に寄り、cat のお題では猫耳が増える傾向が見えました。事前登録した heldout ＋ 本人評価の基準は満たしておらず、本人評価は未実施です。
